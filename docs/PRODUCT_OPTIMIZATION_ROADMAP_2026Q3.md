# Comet 产品级优化路线图（2026 Q3）

## 结论

Comet 已具备知识库、长期记忆、深度研究、Agent、图谱与可观测等完整能力，但用户目前需要理解多个功能入口，难以快速感受到“它替我记住、组织并推进了什么”。下一阶段不应继续平铺新增模块，而应把产品收敛为一条可复用的价值闭环：

`捕获信息 → AI 结构化理解 → 在任务中调用 → 主动回顾与行动 → 用户纠错 → 系统变得更准`

产品北极星指标：**每周至少一次从“新采集的信息”转化为“被用户采用的结论或行动”的活跃用户占比（WAU Knowledge-to-Action Rate）**。

## 目标用户与核心场景

| 优先级 | 用户 | 需要完成的事 | 当前摩擦 | 产品机会 |
| --- | --- | --- | --- | --- |
| P0 | 知识工作者 / 学生 | 保存碎片后，未来能快速找回并用于写作、决策或学习 | 上传、搜索、对话、研究分散，首次价值到达慢 | 统一收集箱和“从资料到产出”工作流 |
| P0 | 高频 AI 使用者 | 让 AI 记住偏好、项目背景和纠正结果 | 记忆价值不可预期，用户难判断何时被调用 | 记忆可见、可控、可纠错、可引用 |
| P1 | 研究 / 项目驱动用户 | 持续追踪课题，产出可信且可复用的报告 | 深度研究是一次性任务，缺乏主题沉淀与后续行动 | 项目空间、主题更新、结论与待办沉淀 |
| P2 | AI 重度玩家 | 配置模型、Agent、MCP 和技能 | 配置入口多、专业门槛高 | 分层配置：默认可用，高级模式再展开 |

## 产品策略：先收敛，再增强

### 1. 重构信息架构为三层

1. **工作台**：今天该看什么、继续什么、处理什么；替代“功能总览”。
2. **知识空间**：收集箱、项目、资料、记忆与搜索统一归属到一个可理解的上下文。
3. **智能能力层**：聊天、研究、自动化、Agent、模型、MCP 等作为完成任务的手段，而不是一级目的地。

建议一级导航收敛为：`工作台 / 知识空间 / 对话 / 研究与任务 / 发现`，将图谱、追踪、模型、技能、通知等移入“发现”或“设置与高级”。原有路由保持兼容，避免迁移成本。

### 2. 建立“收集箱”作为统一入口（P0）

支持文件、网页、图片、文字、语音的统一投递。每条内容自动展示：解析状态、所属空间、AI 摘要、建议标签、重复项提示、下一步建议（问答 / 加入项目 / 生成卡片 / 稍后处理）。

关键体验：用户无需先选择知识库、标签、项目；先放入收集箱，再由 AI 预分类，用户只做轻量确认。

### 3. 用“项目空间”替代孤立知识库（P0）

项目是用户真正关心的工作上下文，包含资料、对话、记忆、研究报告、待办和最近结论。知识库保留为底层存储概念，不作为核心心智模型。

项目首页应回答四件事：

- 这个项目目前的目标是什么？
- 已经掌握了哪些可信结论？
- 哪些信息过期、冲突或尚待确认？
- 下一步最值得做什么？

### 4. 将“搜索结果”升级为“可信答案工作台”（P0）

搜索和对话统一使用证据卡：结论、来源、引用段落、置信度、适用范围、更新时间与“加入项目/纠正/继续追问”。

回答必须区分：来自个人资料、来自记忆、来自联网搜索、AI 推断。用户可以一键固定结论、标记过期或纠正，反馈回写现有记忆审查与评测链路。

### 5. 把主动性设计为“可授权的提醒”，而非打扰（P1）

每日回顾、定时研究和主动关心统一进入“智能简报”。默认只推送三类高价值事件：待处理资料、项目变化、用户承诺的提醒。每条简报都有“为什么现在提醒我”“减少此类提醒”“关闭自动化”入口。

## 90 天路线图

| 阶段 | 周期 | 交付 | 核心验收 |
| --- | --- | --- | --- |
| 0：基线 | 第 1-2 周 | 事件埋点、漏斗看板、现有导航与空状态审计 | 能看到激活、采集、检索、采纳、留存的完整漏斗 |
| 1：首次价值 | 第 3-5 周 | 新手引导、统一收集箱、处理状态、空状态行动入口 | 新用户可在 10 分钟内完成“导入一份资料并得到带引用答案” |
| 2：上下文沉淀 | 第 6-9 周 | 项目空间 V1、证据卡、结论固定、项目内全局搜索 | 用户可从任一资料或对话回到所属项目，并找到来源 |
| 3：持续价值 | 第 10-12 周 | 智能简报、待办/过期提示、反馈闭环、渐进式高级设置 | 每周活跃用户中，知识转行动比例连续 4 周提升 |

## 指标体系与事件定义

| 层级 | 指标 | 定义 |
| --- | --- | --- |
| 激活 | 首次价值完成率 | 注册后 24 小时内，完成采集且获得至少一次带引用结果 |
| 核心价值 | Knowledge-to-Action Rate | 周内新采集内容被引用、固定为结论、加入项目或生成任务的用户占比 |
| 信任 | 可验证回答占比 | 含可打开来源与引用片段的回答占比；另看用户纠错率 |
| 留存 | D7 / W4 留存 | 按“完成首次价值”的用户分群，不只看注册分群 |
| 质量 | 任务成功率与 P95 耗时 | 上传解析、检索、研究任务分别监控成功率、失败原因与等待时间 |
| 成本 | 单次有效行动成本 | LLM 成本 / 被采纳的结论、任务或报告数 |

优先埋点：`onboarding_completed`、`capture_created`、`capture_processed`、`answer_cited`、`source_opened`、`conclusion_saved`、`project_created`、`project_context_used`、`memory_corrected`、`briefing_actioned`。

## 关键体验规范

1. **状态必须可解释**：任何异步处理都展示阶段、预估等待、失败原因与重试入口，不能只显示“处理中”。
2. **来源必须可追溯**：任何 AI 结论均可回到原文、记忆或联网结果；推断须明确标注。
3. **记忆必须可控**：写入前可选择范围，写入后可查看、编辑、删除和禁止调用；敏感记忆默认不主动展示或推送。
4. **高级能力渐进披露**：模型、MCP、技能、Trace 只在“高级”区展示；首用提供推荐默认值与连通性检查。
5. **桌面与移动同等完成任务**：移动端优先支持采集、阅读、追问、确认与稍后处理，不要求完成复杂管理操作。

## 不建议投入的方向

- 在核心闭环未验证前继续增加独立一级模块。
- 将 Trace、模型参数、评测指标直接作为普通用户的默认界面内容。
- 未建立来源与反馈机制前，增加更强的自动写入、自动执行能力。
- 仅以“上传量、对话次数”判断增长；它们不能代表知识真正被使用。

## 当前建议的首个产品迭代（立即开工）

**主题：首次价值闭环 V1。**

范围：新手引导、收集箱、文档处理状态、带引用的首个答案、三个空状态（知识空间 / 项目 / 记忆）以及对应埋点。该迭代不改变现有 RAG、记忆和任务底层能力，优先通过编排现有能力让用户在第一天就明确得到价值。

上线门槛：首次价值完成率、处理成功率、引用打开率均有基线；没有基线不进入下一阶段的功能扩展。

## 迭代记录

### 2026-07-20：首次价值闭环 V1（第一批）

- 新增“收集箱”入口，统一文件上传与网页保存；用户可先选择知识空间，再采集资料。
- 收集结果即时呈现为“上传中 / 已进入解析队列 / 导入失败”，并说明资料后续如何被检索和引用。
- 工作台主行动与新手任务从“管理知识库”调整为“收集资料”，缩短首次价值路径。
- 原有知识库详情页的异步解析、轮询、失败重试保持不变，避免重造底层能力。

下一批：补齐首次价值漏斗埋点与“解析完成后，基于该资料发起提问”的一键入口；在有真实使用数据后再确定项目空间 V1 的信息架构。

### 2026-07-20：首次价值闭环 V1（第二批）

- 收集箱按文档状态轮询；资料解析成功后显示“基于此资料提问”，失败时显示失败状态。
- 提问入口预填“总结核心要点 + 下一步关注问题”，让用户可直接发送或按需要改写。
- 新增 `product_events` 事件表和受登录保护的写入接口，记录 `capture_created`、`capture_processed`、`source_question_started` 三个漏斗节点；属性仅包含文档、来源和入口上下文，不记录资料正文或对话内容。
- 发布时执行 `alembic upgrade head`，使埋点表生效。

### 2026-07-20：项目空间 V1

- 项目详情升级为行动工作台：显示项目目标、资料/对话/研究/任务沉淀，并按当前状态推荐唯一的下一步行动。
- 项目内“收集资料”进入带项目上下文的收集箱，优先选中该项目已有的资料库；资料完成解析后仍可一键发起基于资料的提问。
- 空项目按“建资料库 → 专题对话 → 研究交付 → 持续收集”的顺序引导，减少用户面对空白工作台时的决策成本。

下一批：基于 `product_events` 建立首值漏斗看板，验证激活链路各节点转化；再根据流失节点优化引导，而非继续扩张入口。

### 2026-07-20：首次价值漏斗看板 V1

- 新增个人范围的 `GET /api/product-events/first-value` 聚合接口，统计近 30 天的收集、解析完成、基于资料提问及两段转化率。
- 工作台新增“资料到行动”卡片：按实际漏斗状态只推荐一个补救动作（收集、等待解析、基于资料提问或进入主题空间）。
- 事件数据严格按当前用户隔离，且仅保存流程标识与匿名业务 ID，不保存资料正文或对话内容。

决策规则：先观察真实漏斗中“收集→解析”和“解析→提问”的转化；只有确认具体流失节点后，才针对性改进引导、解析可靠性或提问模板。

### 2026-07-20：可信答案信号 V1

- 将“基于资料提问”的价值信号拆分为：进入资料问题、实际提交问题、收到带引用回答，避免把仅进入对话误判为已获得价值。
- 对话回答中的引用标签改为可点击行动，跳转到对应资料的全局搜索，并记录来源回看行为。
- 继续只记录流程元数据（来源 ID、来源类型、引用数量），不记录原文和对话正文。

下一批：在有足够使用数据后，按“解析失败 / 未发起提问 / 无引用回答 / 未回看来源”四类问题选择一项优化；不同时启动多个未经验证的功能分支。

### 2026-07-25：可信答案五段漏斗

- 工作台漏斗扩展为“收集 → 解析 → 实际提交问题 → 获得带引用回答 → 回看来源”五个真实价值节点。
- 各节点数量按漏斗单调归一，处理重复点击引用、跨统计窗口完成任务等情况，确保转化率不会超过 100%。
- 针对每个断点提供唯一动作：继续收集、查看解析、基于资料提问、优化问题，或回看最近回答。

下一批：补齐解析失败原因分层与可操作恢复入口，优先降低首个技术性流失节点。

### 2026-07-25：端到端优化闭环 V1

- 解析失败按输入限制、内容解析、模型配置、服务异常和未知问题分层展示，并给出对应恢复建议。
- 已创建的失败资料可在收集箱原地重试；恢复成功后自动回到“基于资料提问”状态，无需重新上传。
- 新增失败、重试、恢复事件，工作台优先提示未恢复失败项；失败与恢复按文档去重，重复重试不会夸大未恢复数量。
- 当前完整闭环：`资料收集 → 异步解析 → 失败解释/重试恢复 → 基于资料提问 → 实际提交 → 带引用回答 → 来源核验 → 主题空间持续沉淀`。

至此，产品级 V1 闭环完成。后续进入持续运营阶段：依据真实漏斗数据每次只优化最大流失节点，并以转化率、失败恢复率、引用率和来源核验率验证效果。

### 2026-07-25：生产验收完成

应用容器已更新，数据库迁移到最新 head，四项存储健康；后端 21 项测试、前端 lint/生产构建及 50 项桌面与移动视觉回归全部通过。详细证据见 `docs/PRODUCTION_ACCEPTANCE_2026-07-25.md`。
